> **기준** : 브랜치 `origin/feature/systemRefactoring`, 커밋 `4eb1a58` + 작업 트리 (「슬라이더 드래그 구현 계획」 구현분, `FacilityB` 추가분, `StartDrag` / `StopDrag`의 `SetInputLocked` 주석 처리 상태)
> **목적** : 슬라이더를 잡고 있는 동안 시점을 완전히 멈추지 않고, **매우 낮은 감도로 계속 움직이게** 한다. 이동은 계속 멈춘다.
> **바뀌는 규칙** : 「게임 진행 규칙」 7장 설비 B의 "(기본안) 슬라이더를 잡고 있는 동안 시점 회전과 이동을 멈춘다" → "이동은 멈추고, 시점은 매우 낮은 감도로 움직인다" (11장)

## 1. 배경

### 요청
- 슬라이더를 잡으면 시점이 딱 멈추는 것이 부자연스럽다. 완전히 멈추지 말고, 감도가 매우 낮은 상태로라도 움직이게 한다.

### 현재 코드 상태

| 항목 | 상태 | 결과 |
| --- | --- | --- |
| `FirstPersonController.StartDrag` / `StopDrag` | `SetInputLocked(true/false)` 호출이 **주석 처리**되어 있음 | 드래그 중에도 **시점이 원래 감도로 돌고, WASD 이동도 된다** |
| `FirstPersonCamera` | 감도(`sensitivity`)는 고정값 하나. 잠금(`SetLookLocked`)은 켬 / 끔만 있음 | 감도를 낮추는 방법이 없다 |
| `FacilitySlider.BeginDrag` | 화면에 보이는 레일 축(`_screenAxis`)을 **잡는 순간 한 번만** 계산 | "드래그 중에는 카메라가 고정된다"는 전제에 기대고 있다. 시점이 움직이면 이 전제가 깨진다 |
| 마우스 이동량 | PlayerInput `Look` → `FirstPersonCamera.OnLook`과 `FirstPersonController.OnLook` 둘 다 받음 | 같은 마우스 이동이 시점과 슬라이더 **양쪽에** 들어간다 |

## 2. 범위

| 포함 | 제외 |
| --- | --- |
| `FirstPersonCamera` : 시점 감도 배율 API | 슬라이더마다 다른 시점 감도 (D4) |
| `FirstPersonController` : 드래그 중 이동 정지, 시점 감도 배율 요청, 잠금 호출 정리 | 드래그 중 카메라가 손잡이를 자동으로 따라가는 연출 (4장 방안 D) |
| `FacilitySlider` : 레일 축을 매 프레임 다시 계산 | 매뉴얼 확대 보기 (완전 잠금은 기존 `SetInputLocked` 그대로) |
| 수치 조정 기준, 규칙 문서 갱신 목록 | `FacilityB` 규칙 보완 |

## 3. 핵심 문제 : 마우스 한 번이 두 곳을 움직인다

시점이 움직이면 같은 마우스 이동이 **손잡이도 움직이고, 시점도 돌린다.** 여기서 두 가지 문제가 생긴다.

### 3.1 화면상 레일 축이 낡는다
- 지금은 잡는 순간 계산한 `_screenAxis`를 놓을 때까지 쓴다.
- 시점이 돌면 레일이 화면에서 차지하는 위치 · 방향 · 길이가 바뀐다. 낮은 감도라도 오래 끌면 차이가 쌓인다.
- 해결 : **`Drag`할 때마다 축을 다시 계산한다** (7장). `WorldToScreenPoint` 두 번이므로 비용은 무시할 수준이다.

### 3.2 손잡이가 조준선 기준으로 덜 움직여 보인다
마우스를 위로 `d` 픽셀 움직이면
- 손잡이는 레일을 따라 화면상 `d × weight` 픽셀만큼 위로 간다 (레일 기준으로는 정확하다).
- 동시에 시점이 위로 돌아서, 화면의 모든 것(레일 · 손잡이 포함)이 `r × d` 픽셀만큼 아래로 밀린다.
- 결과 : **레일 대비 손잡이 움직임은 그대로**지만, 조준선 대비 손잡이 움직임은 `d × (weight − r)`로 줄어든다.

`r`(시점 끌림 비율)은 이렇게 어림한다.

```
r ≈ sensitivity × lookScale × (화면 높이 / 2) / tan(세로 FOV / 2) × (π / 180)
```

1080p, 세로 FOV 60°일 때 1도당 약 16 픽셀이다. 카메라 `sensitivity` 0.1 기준으로 계산하면 다음과 같다.

| `dragLookScale` | r | weight 1.0 손잡이 (조준선 기준) | weight 0.3 손잡이 (조준선 기준) |
| --- | --- | --- | --- |
| 0 (지금 계획의 완전 정지) | 0 | 100% | 30% |
| **0.1 (기본안)** | **약 0.16** | **약 84%** | **약 14%** |
| 0.2 | 약 0.33 | 약 67% | 거의 멈춰 보임 |
| 1.0 (현재 주석 처리 상태) | 약 1.6 | 반대 방향으로 밀려 보임 | 반대 방향으로 밀려 보임 |

- **`r`이 가장 무거운 슬라이더의 weight(0.3)보다 충분히 작아야 한다.** 그렇지 않으면 무거운 슬라이더를 끌 때 손잡이가 조준선 기준으로 멈추거나 거꾸로 가는 것처럼 보인다.
- 그래서 기본값을 **0.1**로 잡는다. 플레이하며 0.05 ~ 0.15 사이에서 조정한다.
- 레일 대비 움직임은 정확하고 끄는 소리도 나므로, 플레이어가 "움직이고 있다"는 것은 알 수 있다.

## 4. 방식 비교 (D1)

| 방안 | 마우스 이동을 어떻게 나누나 | 장점 | 단점 |
| --- | --- | --- | --- |
| **A. 같은 이동량을 양쪽에** | 슬라이더 : 전부 (× weight) / 시점 : 전부 × `dragLookScale` | 가장 단순하다. 손은 슬라이더를 끌고 고개도 살짝 따라가는 자연스러운 느낌 | 3.2의 끌림. 배율을 낮게 유지해야 한다 |
| B. 축으로 나눔 | 레일 방향 성분 → 슬라이더만 / 수직 성분 → 시점만 (× 배율) | 이중 움직임이 없다 | 세로 슬라이더면 시점이 좌우로만 돈다. 비스듬히 끌 때 느낌이 어색하다 |
| C. 완전 정지 (원래 계획) | 슬라이더 : 전부 / 시점 : 없음 | 계산이 정확하다 | 이번 요청과 맞지 않는다 |
| D. 카메라 자동 추적 | 슬라이더 : 전부 / 시점 : 손잡이 쪽으로 천천히 자동 회전 | 손잡이가 항상 화면 중앙 근처에 있다 | 플레이어가 조작하는 시점이 아니다. 요청과 다르다 |

**기본안 : A.** 3.2의 끌림은 배율을 낮게 두면 충분히 작다. 플레이해 보고 끌림이 거슬리면 B로 바꾼다. B는 컨트롤러가 이동량을 나눠 카메라에 넘겨야 하므로 A보다 구조 변경이 크다.

## 5. FirstPersonController 변경

### 추가 인스펙터 필드

| 필드 | 타입 | 기본값 | 설명 |
| --- | --- | --- | --- |
| `dragLookScale` | float (Range 0 ~ 1) | 0.1 | 드래그 중 시점 감도 배율. 0이면 완전 정지 (원래 계획과 같음) |

### 동작 변경

| 위치 | 지금 | 변경 |
| --- | --- | --- |
| `StartDrag` | 주석 처리된 `SetInputLocked(true)`, `Debug.Log` | 둘 다 지우고 `firstPersonCamera.SetLookScale(dragLookScale)` |
| `StopDrag` | 주석 처리된 `SetInputLocked(false)` | 지우고 `firstPersonCamera.SetLookScale(1f)` |
| `Move` | `IsInputLocked`일 때만 멈춤 | **`IsInputLocked || IsDragging`** 이면 멈춤 (D2) |
| `OnClick` (누름) | `IsInputLocked`면 무시 | `IsInputLocked || IsDragging`이면 무시 (안전장치. 같은 버튼이라 실제로는 드래그 중 누름이 오지 않는다) |
| `StopDrag` 주석 | "잠금 카운트가 한 번만 줄어든다" | "시점 감도가 한 번만 복구된다"로 고친다 |

- **드래그는 더 이상 잠금 카운트(`_lockCount`)를 쓰지 않는다.** 잠금 카운트는 시점까지 완전히 멈추는 용도(매뉴얼 확대 보기)로만 남는다.
- 강제 종료 경로(뗌 · Esc · 포커스 상실 · 비활성화)는 모두 `StopDrag`를 거치므로, 감도 복구도 자동으로 따라온다. 경로를 새로 만들 필요가 없다.
- `SetInputLocked` 주석의 "(슬라이더 드래그, 매뉴얼 확대 보기용)"은 "(매뉴얼 확대 보기용)"으로 고친다.

### 흐름

```
좌클릭 누름 → 손잡이 Raycast → StartDrag
     ├ _dragTarget 저장                      → Move()가 이동을 멈춘다
     ├ firstPersonCamera.SetLookScale(0.1)   → 시점은 1/10 감도로 계속 돈다
     └ FacilitySlider.BeginDrag(cam)         → 카메라 참조 저장, 축 계산

누른 채 마우스 이동
     PlayerInput Look ─┬→ FirstPersonCamera.OnLook      → 감도 × 0.1로 회전
                       └→ FirstPersonController.OnLook  → _dragDelta 누적
     Update → FacilitySlider.Drag(delta)                 → 축을 다시 계산하고 손잡이 이동

뗌 / Esc / 포커스 상실 / 비활성화 → StopDrag
     ├ FacilitySlider.EndDrag()
     └ firstPersonCamera.SetLookScale(1)     → 원래 감도, 이동 재개
```

## 6. FirstPersonCamera 변경

### 추가 내부 상태 · 공개 API

| 멤버 | 설명 |
| --- | --- |
| `_lookScale : float` | 감도 배율. 기본 1 |
| `void SetLookScale(float scale)` | 배율 지정. 0 미만은 0으로 자른다. 1이면 원래 감도 |

### 동작 변경
- `Update`의 회전 계산 : `delta = _lookInput * sensitivity * _lookScale`
- `SetLookLocked(true)`가 배율보다 우선한다. 잠겨 있으면 배율과 상관없이 돌지 않는다 (지금 순서 그대로 : 잠금 검사가 먼저).
- 배율 요청자는 드래그 하나뿐이므로 카운트 없이 값 하나로 둔다. 요청자가 늘어나면 그때 스택이나 최솟값 방식으로 바꾼다.

## 7. FacilitySlider 변경

| 위치 | 지금 | 변경 |
| --- | --- | --- |
| `BeginDrag(cam)` | 축을 계산해 `_screenAxis`에 저장 | 카메라를 `_dragCamera`에 저장하고, 축 계산은 `RecalculateScreenAxis()`로 분리해 호출 |
| `Drag(delta)` | 저장된 `_screenAxis` 사용 | **먼저 `RecalculateScreenAxis()`** 한 뒤 투영 |
| `EndDrag()` | | `_dragCamera = null` |
| `BeginDrag` 주석 | "드래그 중에는 카메라가 고정되므로 … 한 번만 계산한다" | "드래그 중에도 시점이 움직이므로 매 프레임 다시 계산한다"로 고친다 |

**RecalculateScreenAxis**
1. `start = cam.WorldToScreenPoint(railStart.position)`, `end = cam.WorldToScreenPoint(railEnd.position)`
2. 둘 중 하나라도 `z <= 0`(카메라 뒤)이면 **이전 축을 그대로 쓴다.** 낮은 감도에서는 거의 일어나지 않지만, 축이 뒤집혀 손잡이가 거꾸로 가는 것을 막는다.
3. 나머지는 지금 계산과 같다 (최소 길이 보정 포함).

- 실행 순서 : 같은 프레임 안에서 컨트롤러의 `Drag`와 카메라의 회전 중 무엇이 먼저 실행될지는 정해져 있지 않다. 차이는 낮은 감도 한 프레임치 회전이라 느낄 수 없는 수준이므로, Script Execution Order는 건드리지 않는다.

## 10. 작업 순서

1. `FirstPersonCamera` : `_lookScale`, `SetLookScale()`, 회전 계산에 배율 적용
2. `FirstPersonController` : `dragLookScale` 필드, `StartDrag` / `StopDrag`에서 배율 요청 · 복구, 주석 처리된 잠금 호출과 `Debug.Log` 정리, `Move` / `OnClick`에 `IsDragging` 조건
3. `FacilitySlider` : `_dragCamera` 저장, `RecalculateScreenAxis()` 분리, `Drag`마다 재계산, 카메라 뒤 보호
4. 테스트 씬에서 weight 1.0과 0.3 슬라이더로 11장 확인, `dragLookScale` 조정
5. 규칙 문서 갱신 (12장)
